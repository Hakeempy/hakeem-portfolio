## The problem

A model in a notebook only helps whoever opens the notebook. The aim was to let anyone, without writing
any Python, enter a few details about themselves and get an estimate of their health insurance cost
from a trained model.

## How it works

1. The training data has 1,338 policies with age, sex, BMI, number of children, smoking status, region
   and charges. The text columns are mapped to numbers, and 80% of the rows train four models: linear
   regression, support vector regression, random forest and gradient boosting.
2. On the remaining 20%, gradient boosting scores best, with an R² of 0.88 and a mean absolute error of
   about 2,450, against 0.78 and about 4,190 for linear regression.
3. Gradient boosting is retrained on all 1,338 rows and saved with Joblib.
4. `ML_web_app.py` is a Streamlit app that loads the saved model and asks for age, sex, BMI, number of
   children, smoking status and region. When you press Predict, it encodes the answers the way the
   training data was encoded and shows the estimated cost.
5. A Procfile and a setup script run Streamlit headless on the port the host provides, and a dev
   container configuration starts the app in GitHub Codespaces.

## Decisions worth explaining

- **Choose on held-out data, then train on everything.** The comparison uses a test split, but the
  saved model is refit on every row, so the app does not lose a fifth of the data.
- **Gradient boosting over the simpler model.** Both tree ensembles cut the average error by about 40%
  compared with linear regression, and gradient boosting edged out the random forest.
- **Streamlit instead of a desktop window.** The notebook ends with a Tkinter form that only works on
  the computer running it. Streamlit turned the same model into a web page with one short Python file.

## What I would change next

Reading the code for this write-up turned up a bug: the branch meant for northwest checked for southwest
a second time, so northwest was sent as the code for northeast. The sliders also allowed ages up to 100
and at most 4 children, outside the training data (ages 18 to 64, up to 5 children). Both are now fixed
in [the app](https://github.com/Hakeempy/ML-WEB-APP/commit/4e3443c). Next I would save the encoding
together with the model in one scikit-learn pipeline, so the app and the training can never drift apart
again.
